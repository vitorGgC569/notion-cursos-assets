NoSQL de documentos: JSONB no PostgreSQL (o modelo de documento do MongoDB, com SQL)
======================================================================
Esquema flexivel: cada documento tem campos diferentes (nota so existe em alguns, extra so em um).
pg> SELECT id, d->>'nome' AS nome, d->'endereco'->>'cidade' AS cidade, (d->>'nota')::numeric AS nota FROM doc ORDER BY id
id | nome | cidade   | nota
---+------+----------+-----
1  | Ana  | Goiania  | 8.5
2  | Bia  | Anapolis | NULL
3  | Caio | NULL     | 6
(3 linhas)
Consultas por conteudo: contem a tag ti; tem a chave nota:
pg> SELECT d->>'nome' AS nome FROM doc WHERE d @> '{"tags":["ti"]}' ORDER BY id
nome
----
Ana
Caio
(2 linhas)
pg> SELECT d->>'nome' AS nome FROM doc WHERE d ? 'nota' ORDER BY id
nome
----
Ana
Caio
(2 linhas)

Grafos: relacionamentos como cidadao de primeira classe (CTE recursiva no lugar do Cypher)
======================================================================
pg> WITH RECURSIVE alcance(pessoa, saltos) AS (
     SELECT para, 1 FROM segue WHERE de = 'ana'
     UNION
     SELECT s.para, a.saltos + 1 FROM alcance a JOIN segue s ON s.de = a.pessoa WHERE a.saltos < 3
   )
   SELECT pessoa, MIN(saltos) AS saltos FROM alcance GROUP BY pessoa ORDER BY saltos, pessoa
pessoa | saltos
-------+-------
bia    | 1
eva    | 1
caio   | 2
dora   | 2
(4 linhas)
Em um banco de grafos (Neo4j) isso seria MATCH (a {nome:"ana"})-[:SEGUE*1..3]->(p) RETURN p. Nao testado aqui.

---------------
0.8.5
(1 linha)
Embeddings de 3 dimensoes inventados para o exemplo (modelos reais usam centenas ou milhares de dimensoes):
Consulta: o vetor [0.88, 0.12, 0.02] (algo como "animal"). <=> e distancia de cosseno, <-> e distancia euclidiana:
pg> SELECT texto, ROUND((emb <=> '[0.88,0.12,0.02]')::numeric, 4) AS dist_cosseno, ROUND((emb <-> '[0.88,0.12,0.02]')::numeric, 4) AS dist_euclid FROM trecho ORDER BY emb <=> '[0.88,0.12,0.02]' LIMIT 4
texto            | dist_cosseno | dist_euclid
-----------------+--------------+------------
gato e cachorro  | 0.0006       | 0.0346
felino domestico | 0.0014       | 0.0520
fatura do cartao | 0.8893       | 1.2166
contas a pagar   | 0.9501       | 1.2828
(4 linhas)
pg> CREATE INDEX idx_trecho_hnsw ON trecho USING hnsw (emb vector_cosine_ops)
OK
pg> EXPLAIN (COSTS OFF) SELECT texto FROM trecho ORDER BY emb <=> ... LIMIT 2
   Limit
     ->  Index Scan using idx_trecho_hnsw on trecho
           Order By: (emb <=> '[0.88,0.12,0.02]'::vector)
(enable_seqscan = off so para forcar o plano com indice na tabela minuscula; o indice HNSW e aproximado (ANN), troca exatidao por velocidade.)

Replicacao assincrona: o primario nao espera o standby confirmar, por isso pode haver perda de dados no failover. A sincrona (synchronous_commit) espera, com custo de latencia. RPO e RTO: veja a teoria.
