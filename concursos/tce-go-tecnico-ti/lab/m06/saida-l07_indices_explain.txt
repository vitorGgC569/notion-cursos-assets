
======================================================================
L7. Indices, B-tree e planos de execucao
======================================================================
SQLite 3.46.1 (modulo sqlite3 do Python 3.13.5)
PostgreSQL 18.4

======================================================================
SQLite
======================================================================
Tabela pessoa com 50000 linhas geradas (dados didaticos). Coluna ativo = 1 em 1% das linhas.
sq> SELECT COUNT(*) AS linhas FROM pessoa
linhas
------
50000
(1 linha)

--- 1. Busca por igualdade SEM indice: varredura da tabela inteira
sq> EXPLAIN QUERY PLAN SELECT * FROM pessoa WHERE cpf = '00000007919'
   SCAN pessoa

--- 2. Cria indice B-tree em cpf e repete
sq> CREATE INDEX idx_pessoa_cpf ON pessoa (cpf)
OK
sq> EXPLAIN QUERY PLAN SELECT * FROM pessoa WHERE cpf = '00000007919'
   SEARCH pessoa USING INDEX idx_pessoa_cpf (cpf=?)

--- 3. Indice UNIQUE faz o papel de restricao e de indice ao mesmo tempo
sq> CREATE UNIQUE INDEX uq_pessoa_nome ON pessoa (nome)
OK
sq> INSERT INTO pessoa VALUES (50001,'x','pessoa1','Goiania',1990,0)
ERRO: UNIQUE constraint failed: pessoa.nome

--- 4. Indice composto: vale o prefixo mais a esquerda
sq> CREATE INDEX idx_cid_nasc ON pessoa (cidade, nascimento)
OK
[usa as duas colunas]
sq> EXPLAIN QUERY PLAN SELECT id FROM pessoa WHERE cidade = 'Goiania' AND nascimento = 1990
   SEARCH pessoa USING COVERING INDEX idx_cid_nasc (cidade=? AND nascimento=?)
[usa so o prefixo cidade]
sq> EXPLAIN QUERY PLAN SELECT id FROM pessoa WHERE cidade = 'Goiania' AND ativo = 1
   SEARCH pessoa USING INDEX idx_cid_nasc (cidade=?)
[so a segunda coluna: nao e o prefixo mais a esquerda]
sq> EXPLAIN QUERY PLAN SELECT id FROM pessoa WHERE nascimento = 1990
   SCAN pessoa USING COVERING INDEX idx_cid_nasc
Leitura: o SQLite varre o indice inteiro (SCAN ... COVERING INDEX); o PostgreSQL 18 faz varias buscas no indice, uma por valor distinto de cidade (skip scan, novo na versao 18; veja Index Searches). Nos dois casos a coluna lider continua sendo a mais importante.

--- 5. Funcao sobre a coluna impede o uso do indice (nao "sargable")
sq> EXPLAIN QUERY PLAN SELECT * FROM pessoa WHERE substr(cpf, 1, 5) = '00000'
   SCAN pessoa
sq> EXPLAIN QUERY PLAN SELECT * FROM pessoa WHERE cpf >= '00000' AND cpf < '00001'
   SEARCH pessoa USING INDEX idx_pessoa_cpf (cpf>? AND cpf<?)

--- 6. Baixa seletividade: indice em coluna com poucos valores distintos
sq> CREATE INDEX idx_ativo ON pessoa (ativo)
OK
[ativo = 1 (1% das linhas): raro, o indice compensa]
sq> EXPLAIN QUERY PLAN SELECT * FROM pessoa WHERE ativo = 1
   SEARCH pessoa USING INDEX idx_ativo (ativo=?)
[ativo = 0 (99% das linhas): o otimizador prefere ler a tabela toda]
sq> EXPLAIN QUERY PLAN SELECT * FROM pessoa WHERE ativo = 0
   SEARCH pessoa USING INDEX idx_ativo (ativo=?)

--- 7. Indice parcial (somente as linhas ativas) e indice de cobertura
sq> CREATE INDEX idx_ativos_parcial ON pessoa (nome) WHERE ativo = 1
OK
sq> CREATE INDEX idx_cobre ON pessoa (cidade, nome)
OK
[COVERING INDEX: a resposta sai do proprio indice]
sq> EXPLAIN QUERY PLAN SELECT cidade, nome FROM pessoa WHERE cidade = 'Catalao'
   SEARCH pessoa USING COVERING INDEX idx_cobre (cidade=?)
sq> SELECT name FROM sqlite_master WHERE type = 'index' AND tbl_name = 'pessoa' ORDER BY 1
name
------------------
idx_ativo
idx_ativos_parcial
idx_cid_nasc
idx_cobre
idx_pessoa_cpf
uq_pessoa_nome
(6 linhas)

--- 8. Ordenacao: o indice evita o SORT
sq> EXPLAIN QUERY PLAN SELECT * FROM pessoa ORDER BY nome LIMIT 3
   SCAN pessoa USING INDEX uq_pessoa_nome
sq> EXPLAIN QUERY PLAN SELECT * FROM pessoa ORDER BY nascimento, nome LIMIT 3
   SCAN pessoa
   USE TEMP B-TREE FOR ORDER BY

--- 9. JOIN: a chave estrangeira sem indice obriga varredura
[sem indice em pedido.pessoa_id]
sq> EXPLAIN QUERY PLAN SELECT p.nome, SUM(o.valor) FROM pessoa p JOIN pedido o ON o.pessoa_id = p.id WHERE p.cpf = '00000300922' GROUP BY p.nome
   SCAN o
   SEARCH p USING INTEGER PRIMARY KEY (rowid=?)
   USE TEMP B-TREE FOR GROUP BY
sq> CREATE INDEX idx_pedido_pessoa ON pedido (pessoa_id)
OK
[com indice em pedido.pessoa_id]
sq> EXPLAIN QUERY PLAN SELECT p.nome, SUM(o.valor) FROM pessoa p JOIN pedido o ON o.pessoa_id = p.id WHERE p.cpf = '00000300922' GROUP BY p.nome
   SEARCH p USING INDEX idx_pessoa_cpf (cpf=?)
   SEARCH o USING INDEX idx_pedido_pessoa (pessoa_id=?)
   USE TEMP B-TREE FOR GROUP BY

--- 10. Custo do indice: toda escrita atualiza tambem os indices
sq> SELECT COUNT(*) AS indices_da_tabela_pessoa FROM sqlite_master WHERE type = 'index' AND tbl_name = 'pessoa'
indices_da_tabela_pessoa
------------------------
6
(1 linha)
